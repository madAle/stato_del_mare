# La corrente disegnata, piano di implementazione

> **Per chi esegue:** SOTTO-SKILL RICHIESTA: usare `superpowers:subagent-driven-development` (consigliata) oppure `superpowers:executing-plans` per eseguire un task alla volta. I passi hanno le caselle (`- [ ]`) per segnare l'avanzamento.

**Obiettivo:** disegnare la corrente come grandezza selezionabile, colore dal modulo della velocità e verso da scie animate, sciogliendo il vincolo che legava l'id di una grandezza all'id di un campo del catalogo.

**Architettura:** i due campi `ubar` e `vbar` viaggiano separati fino allo shader, che interpola nel tempo **le componenti** e solo dopo prende il modulo. `src/data/` non cambia: `leggiIndice` e `urlFrame` prendono già un id di campo, e il fan out sta in chi li chiama, con un `Prefetcher` per campo (lo stesso schema che la direzione dell'onda usa da tre giorni). Il motore delle particelle acquista una seconda sorgente di moto, da (u, v) invece che da (seno, coseno, periodo), e il disegno a scia torna da git accanto a quello a cresta.

**Stack:** TypeScript, React 19, MapLibre GL 5, WebGL2 (shader GLSL ES 3.00), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-21-corrente-design.md`. Il piano argomenta dalla spec: chi esegue legge entrambi.

```ts
/** La geometria comune, uguale per qualunque campo di moto. */
export type Geometria = {
  larghezza: number;
  altezza: number;
  /** Metri di Mercatore per cella. */
  risoluzioneM: number;
  /** Coordinata y di Mercatore del bordo nord, per ricavare la latitudine. */
  yMax: number;
};

/**
 * Un campo da cui ricavare un moto, in due forme.
 *
 * **Onda**: seno e coseno della direzione da cui viene, piu' il periodo, da cui
 * la celerita' `c = g T / 2 pi`. Il verso e' mezzo giro rispetto all'angolo.
 *
 * **Corrente**: le due componenti della velocita'. Il verso e' quello delle
 * componenti, **senza** mezzo giro, e la velocita' e' il loro modulo: qui il
 * dato e' la velocita', non un periodo da cui ricavarla.
 *
 * Sono un'unione discriminata e non due funzioni separate perche' tutto quello
 * che sta a valle (la cresta, il ricambio delle particelle, la correzione di
 * Mercatore) e' identico: separarle vorrebbe dire due copie di quella roba, che
 * e' il modo in cui fra sei mesi divergono.
 */
export type CampiMoto =
  | ({ tipo: "onda"; sin: Float32Array; cos: Float32Array; periodo: Float32Array } & Geometria)
  | ({ tipo: "corrente"; u: Float32Array; v: Float32Array } & Geometria);
```

```ts
export function velocitaInCelle(
  campi: CampiMoto, i: number, j: number,
): { di: number; dj: number } | null {
  const ii = Math.floor(i);
  const jj = Math.floor(j);
  if (ii < 0 || jj < 0 || ii >= campi.larghezza || jj >= campi.altezza) return null;
  const k = jj * campi.larghezza + ii;

  let est: number;
  let nord: number;
  let metriAlSecondo: number;

  if (campi.tipo === "onda") {
    const s = campi.sin[k];
    const c = campi.cos[k];
    const t = campi.periodo[k];
    if (!Number.isFinite(s) || !Number.isFinite(c) || !Number.isFinite(t) || t <= 0) return null;
    const modulo = Math.hypot(s, c);
    if (modulo < 0.5) return null;
    // Dove l'onda **va**: mezzo giro rispetto a dove viene.
    est = -s / modulo;
    nord = -c / modulo;
    metriAlSecondo = VELOCITA_PER_SECONDO_DI_PERIODO * t;
  } else {
    const u = campi.u[k];
    const v = campi.v[k];
    if (!Number.isFinite(u) || !Number.isFinite(v)) return null;
    // La velocita' **e'** il modulo, e il verso e' quello delle componenti:
    // niente mezzo giro, perche' u e v dicono gia' dove l'acqua va.
    metriAlSecondo = Math.hypot(u, v);
    if (metriAlSecondo <= 0) return null;
    est = u / metriAlSecondo;
    nord = v / metriAlSecondo;
  }

  const celleAlSecondo = metriAlSecondo / (Math.cos(latitudineDi(campi, jj)) * campi.risoluzioneM);
  return { di: est * celleAlSecondo, dj: -nord * celleAlSecondo };
}
```

```ts
/**
 * Il modulo di una grandezza a due componenti, sotto il cursore.
 *
 * **L'ordine non e' negoziabile**: si interpolano nel tempo le due componenti,
 * ognuna col percorso di `valoreCorrente`, e solo dopo si prende il modulo.
 * Mescolare i moduli sbaglia proprio all'inversione di marea, dove una
 * componente passa da +0,3 a -0,3 e il valore vero a meta' e' zero mentre la
 * media dei moduli da' 0,3: una corrente che non si annulla mai. E' lo stesso
 * principio per cui il catalogo archivia seno e coseno di un angolo invece
 * dell'angolo, scritto in `ui/grandezze.ts`.
 *
 * Se una delle due componenti non ha dato, non c'e' valore: meta' di un vettore
 * non e' un vettore, e dare zero all'altra darebbe una corrente piu' lenta del
 * vero, cioe' un numero plausibile e falso.
 */
export function valoreVettore(
  griglia: Griglia,
  ore: Ora[],
  istante: number,
  prendiU: (ora: Ora) => Int16Array | undefined,
  prendiV: (ora: Ora) => Int16Array | undefined,
  lon: number,
  lat: number,
  scala: number,
  offset: number,
  dissolvenza = true,
): number | null {
  const u = valoreCorrente(griglia, ore, istante, prendiU, lon, lat, scala, offset, dissolvenza);
  const v = valoreCorrente(griglia, ore, istante, prendiV, lon, lat, scala, offset, dissolvenza);
  if (u === null || v === null) return null;
  return Math.hypot(u, v);
```

```glsl
  // Nell'ordine opposto la corrente non si annullerebbe mai: all'inversione di
  // marea una componente passa da +0,3 a -0,3 e il valore vero a meta' e' zero,
  // mentre la media dei moduli da' 0,3. Non si vede come un errore, si vede

  float c2;

    float pesoB2 = pesoB;

    if (u_modulo && pesoA2 <= 0.0 && pesoB2 <= 0.0) { fragColor = vec4(0.0); return; }

    // con zero, che sarebbe un campo che sprofonda e risale a ogni ora.
    c1 = pesoA <= 0.0 ? vb : (pesoB <= 0.0 ? va : mix(va, vb, u_frazione));

    c2 = va2;
```

```ts
              ? valoreVettore(
                  catalogo.griglia, asseRef.current, ultimoIstante.current,

                  (ora) => cache.prendi(p[1].chiave(ora)),
                  dove.lng, dove.lat,
```

In `MapView`, costruire un **secondo** livello di particelle accanto a quello della direzione, e alimentarlo dai prefetcher del **campo**: `ubar` e `vbar` sono già in cache perché il colore li sta disegnando, quindi le scie non costano **nessuna richiesta in più** (e non serve un secondo asse dei tempi, al contrario della direzione dell'onda, i cui campi sono altri).

```ts
        const scie = new LivelloParticelle("corrente-scie", catalogo.griglia, "scia");
        m.addLayer(scie);

        const aggiornaScie = () => {
          const p = prefetcherCampiRef.current;
          // Solo per una grandezza a due componenti: sulle altre non c'e'
          // nessun vettore da mostrare, e lasciare le scie accese su un dato
          // vecchio sarebbe un'animazione bellissima e falsa.
          if (p.length < 2 || asseRef.current.length === 0) { scie.svuota(); return; }
          const q = inquadraOre(asseRef.current, ultimoIstante.current);
          if (!q) { scie.svuota(); return; }
          const chiesti = p.map((pf) => [
            cache.prendi(pf.chiave(q.prima)),
            q.dopo ? cache.prendi(pf.chiave(q.dopo)) ?? null : null,
          ] as const);
          // Se manca un fotogramma non si disegna niente, invece di mescolare
          // componenti di istanti diversi.
          if (chiesti.some(([a]) => !a)) return;
          scie.imposta(
            { tipo: "corrente" },
            chiesti[0][0]!, q.dopo ? chiesti[0][1] : null,
            chiesti[1][0]!, q.dopo ? chiesti[1][1] : null,
            q.dopo && chiesti.every(([, b]) => b) ? q.frazione : 0,
            variabileRef.current.scala,
          );
        };
```

`LivelloParticelle.imposta` va quindi generalizzata per accettare **due** forme di sorgente: tre campi con due scale per l'onda (come oggi), due campi con una scala per la corrente. Chi esegue scelga la firma che gli sembra meno brutta fra un primo parametro discriminante (come sopra) e due metodi separati (`impostaOnda`, `impostaCorrente`); la seconda è probabilmente più leggibile e non ha un tipo da controllare a runtime.

`aggiornaScie` va chiamata dove già si chiama `aggiornaDirezione`: in `animazione.alTempo`, e una volta subito dopo la costruzione.
